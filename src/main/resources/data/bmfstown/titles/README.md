# 称号注册表（data/bmfstown/titles/*.json）

登记制（v0.16 数据结构先行，#104）：称号定义（id→显示文本），可放多个文件，
同 id 首见优先。**mod 内置目录暂空**——具体有哪些称号等用户定稿，先授予后补文案。

## 格式

```json
{
  "titles": [
    { "id": "dragon_slayer", "text": "屠龙者" }
  ]
}
```

## 机制口径

- 镇民侧（`TitleState`，第九域，随实体存档）只存 id：已获得列表（按获得顺序）
  + 当前佩戴单枚（空=未佩戴）；
- 授予幂等；**授予不自动佩戴**；只能佩戴已获得的称号；
- 显示串 = 称号文本 + 名字**直接相连**（无分隔符，用户拍板），未佩戴=原名；
- id 未登记时显示回落 id 本身（绝不因缺文案而炸），`/reload` 补上文案即生效；
- 撤销称号连带摘下佩戴中的同 id；存档里悬空佩戴（Active 不在 Earned 里）
  读档时被拒。

## 展示接线（后补，勿误报）

`Resident.titledName()` 已提供展示串，但**尚未挂任何渲染路径**（名牌/面板/
客户端快照同步都没接）——当前称号在游戏画面上不可见，属设计内状态。
